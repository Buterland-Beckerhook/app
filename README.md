# buterland-beckerhook.de

Website for **Schützenverein Buterland-Beckerhook e.V.**, a German shooting club.
The public site is server-rendered [Phoenix](https://www.phoenixframework.org/)
(HEEx), the admin area is Phoenix LiveView, data lives in PostgreSQL, and uploaded
media is stored on a local volume with libvips-generated responsive WebP variants.

The site was rewritten from an earlier Directus (CMS) + SvelteKit stack; that stack
has been removed and all application code now lives under [`app/`](app/).

| | |
|---|---|
| **Language / runtime** | Elixir + Phoenix (OTP app `:bbh`) |
| **Database** | PostgreSQL 16 |
| **Media** | libvips → responsive WebP, local volume |
| **Delivery** | Docker Compose image on GHCR, behind central Traefik (prod) / Caddy (dev) |
| **CI/CD** | GitHub Actions (`ci.yml` test+audit gate, `build.yml` → GHCR) |

## Development

Dev runs **fully containerized** (`compose.yml`): PostgreSQL + Phoenix (source
bind-mounted with code reload) + Caddy (local HTTPS at `https://localhost`). Use the
repo-root `Makefile`:

```bash
make dev        # Start the dev stack at https://localhost
make down       # Stop the stack (data persists in volumes)
make logs       # Tail the running stack

# The following exec `mix` inside the running phoenix container (stack must be up):
make test       # mix test
make format     # mix format
make precommit  # compile --warnings-as-errors + audits + format + test
make migrate    # mix ecto.migrate
make seed       # Restore ./seed snapshot into the dev DB + uploads
```

`make help` lists every target. Conventions (contexts, LiveView, Ecto, HEEx,
testing) are documented in [`app/AGENTS.md`](app/AGENTS.md).

## Deployment

The image is built by **GitHub Actions** and pushed to **GHCR**
(`ghcr.io/buterland-beckerhook/app`) — the server never builds, it only pulls. A
single `deploy/compose.yml` serves both **beta** and **prod**; the difference lives
entirely in `.env` (generated by `deploy/setup.sh`). TLS, HTTP→HTTPS, compression
and (beta) Basic-Auth/`noindex` are handled by the host's central Traefik.

First-time server setup, the reverse-proxy prerequisites, dump restore and rollback
are all documented in **[`deploy/README.md`](deploy/README.md)**.

### Updating a running server

```bash
cd deploy && ./update.sh        # git pull + docker compose pull + up -d
```

`update.sh` pulls the latest code and image and restarts the stack; migrations run
automatically on Phoenix startup. See the script header for flags.

## Maintenance

- **Backups** — `deploy/backup.sh` runs a nightly `pg_dump` + uploads tarball,
  pushed offsite via Borg (cron as root). See [`deploy/README.md`](deploy/README.md#backups).
- **Restore / re-seed** — drop a `*.dump` into `deploy/restore/`; it loads on the
  next `up` before Phoenix migrates on top. Details in
  [`deploy/README.md`](deploy/README.md#restoring-a-dump).
- **Logs** — `docker compose --env-file .env logs -f phoenix`; verbosity via
  `LOG_LEVEL` in `.env`.
- **BLZ table** (IBAN→BIC lookup for the membership form) — refresh ~quarterly with
  `mix bbh.blz.strip <csv>`; see [`AGENTS.md`](AGENTS.md#blz-table-iban--bickreditinstitut).
- **Dependencies** — Renovate opens weekly update PRs; patch/minor auto-merge once
  `ci.yml` is green, majors wait for review.
